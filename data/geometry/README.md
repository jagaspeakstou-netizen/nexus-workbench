# Geometry Lab sample data — provenance, units, schema

Both files here are **hand-authored / synthetically generated for this
assignment**. Neither is real CAD or ANSYS output, and neither is
represented as such anywhere in this project (per the brief's explicit
requirement).

## `sample_tetrahedron.stl`

- **Provenance:** hand-written ASCII STL, generated by a short script in
  this repo's history (see `docs/architecture/geometry_lab.md`) from 4
  chosen vertices — A=(0,0,0), B=(1,0,0), C=(0,1,0), D=(0,0,1) — a unit
  right tetrahedron. Not exported from any CAD tool.
- **Units:** meters (unitless numerically; the viewer and docs treat the
  coordinates as meters for consistency with the thermal module).
- **Schema:** standard ASCII STL grammar (`solid` / `facet normal` /
  `outer loop` / `vertex` ×3 / `endloop` / `endfacet` / `endsolid`).
- **Expected parse result:** 4 triangles, bounding box
  `(0,0,0)` to `(1,1,1)`.

## `ansys_nodal_temperatures_synthetic.csv`

- **Provenance:** synthetic — a 3×3×3 uniform grid (27 nodes) over a 1 m
  cube, with a hand-picked formula
  `T(x,y,z) = 20 + 30x + 15y + 5z + 10·exp(-d²/0.15)` (`d` = distance to
  the cube center) chosen only to look visually interesting in the
  point-cloud viewer. **This is not real ANSYS solver output** — the
  filename and every UI label that references it say "synthetic"
  explicitly, per the brief's requirement to never represent synthetic
  data as actual ANSYS output.
- **Units:** `x_m, y_m, z_m` in meters; `temperature_C` in degrees
  Celsius.
- **Schema (required, exact header):** `node_id,x_m,y_m,z_m,temperature_C`
- **Expected parse result:** 27 nodes, temperature range ≈ 20–60 °C.

## Limits enforced by the parser

Both `parse_ascii_stl()` and `parse_ansys_csv()`
(`backend/src/geometry/`) reject input over **5 MiB** before attempting
to parse it, and reject non-finite (NaN/Inf) numeric values anywhere in
the file. See `backend/tests/test_geometry.cpp` for the full positive
and negative test matrix.
